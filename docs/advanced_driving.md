# 해운대 드라이브: MVP 이후 세부기획

작성일 2026-11-22. MVP(0~5단계)의 기획과 결과는 `docs/driving.md`에 있다. 이 문서는 그 뒤에 할 일을 정한다.

상태: **진행 중**. 11장의 결정은 모두 권장안으로 확정됐다(2026-11-22). 6~10단계를 마쳤고 다음은 11단계(신호등·표지·가로 시설)다. 단계별 결과는 13장부터 적는다.

## 1. 지금 상태와 목표

MVP는 "실제 지도 위를 달릴 수 있다"까지 만들었다. 달려 보면 아래 네 가지가 비어 있다.

| 빈 곳 | 지금 | 목표 |
|---|---|---|
| 거리가 죽어 있다 | 차도 사람도 없다 | 차가 차로를 따라 다니고 신호를 지킨다. 사람이 인도를 걷고 횡단보도를 건넌다 |
| 차가 장난감 같다 | 옆모습 윤곽을 밀어낸 상자형 차체. 실내는 핸들뿐 | 곡면 차체와 디테일. 계기판·센터 화면·거울이 동작하는 실내 |
| 거리가 단조롭다 | 외벽 무늬 5종 반복, 신호등·표지 최소 형태, 건물의 37%가 추정 | 건물마다 다른 외벽과 1층 상가, 한국식 신호등과 방향 표지, 실제 건물 자료 |
| 도로가 덜 됐다 | 교량 41구간 진입 불가, 지하차도가 지상, 교차로 모서리 끊김 | 교량과 지하차도를 달린다. 교차로가 자연스럽다 |

방향은 그대로다. 경주가 아니라 힐링 드라이빙이고, 실제 지도 기반이며, 링크만 열면 무료로 실행된다. 벌점·미션·파손은 넣지 않는다.

## 2. 전체 원칙

- **성능 예산을 먼저 정한다.** 기준 기기(Intel Iris Xe, 1280×720)에서 "보통" 품질이 낮 50프레임, 비 오는 밤 40프레임 이상이어야 한다. 지금은 59와 48이다. 단계마다 이 수치를 재고, 못 지키면 그 단계의 수량(차 대수, 사람 수)을 줄인다.
- **수량은 품질 옵션에 묶는다.** 교통량과 보행자 수는 낮음·보통·높음에서 다르게 둔다.
- **외부 자료는 조건을 기록한다.** 모델·질감·음원·지도 자료는 출처와 이용 조건을 적고, 표시가 필요한 것은 크레딧 화면에 넣는다. 실제 브랜드 차량과 상호는 계속 쓰지 않는다.
- **단계마다 공개 링크가 동작한다.** 단계가 끝나면 푸시해서 링크로 확인할 수 있어야 한다.
- **검증 방식은 MVP와 같다.** 자동 운전 완주, 수치 측정, 별도 검토자의 코드 검토. 사람 눈으로 봐야 하는 항목은 그렇게 적는다.

## 3. 제작 순서

| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| 6. 차량 외관 | 곡면 차체, 등화류, 휠, 번호판, 방향지시등·경적 | 4종이 옆·앞·뒤 어디서 봐도 차종이 구분된다 |
| 7. 차량 실내 | 계기판, 센터 화면, 룸미러·사이드미러, 시트와 도어 | 운전석 시점만으로 속도·방향·뒤쪽 상황을 알 수 있다 |
| 8. 차로와 신호 체계 | 차로 단위 도로망, 한국식 신호 현시, 보행 신호 | 모든 교차로에서 차로별 진행 경로와 신호가 모순 없이 정해진다 |
| 9. 교통 차량 | 주차 차량, 주행 차량, 버스·택시 | 다른 차가 신호를 지키며 다니고, 30분 주행 동안 교착이 없다 |
| 10. 보행자 | 인도 보행, 횡단, 날씨·시간별 밀도 | 사람이 인도를 걷고 보행 신호에 건넌다. 차도로 끼어들지 않는다 |
| 11. 신호등·표지·가로 시설 | 신호등 모델, 방향 표지, 5장의 빠진 시설물 | 간선 교차로마다 한국식 신호등과 방향 표지가 선다 |
| 12. 건물 | 외벽 다양화, 1층 상가, 옥상, 대표 건물, 실제 건물 자료 | 같은 외벽이 한 화면에 반복돼 보이지 않는다. 추정 건물 비율 10% 이하 |
| 13. 도로 구조와 지형 | 교량, 지하차도, 교차로 모서리, 경사 보정 | 교량과 지하차도를 달려서 지난다 |
| 14. 환경·날씨·소리 | 바다, 원경, 나무 종류, 물웅덩이, 거리 소리 | 5장·6장에서 빠졌던 항목이 채워진다 |
| 15. 편의 기능 | 설정 저장, 목적지 안내, 사진 모드, 라디오 보강 | 새로고침해도 설정이 남고, 목적지를 골라 달릴 수 있다 |
| 16. 지도 확장 | 기장 시골길, 멀어진 구역 내리기 | 해운대에서 기장까지 이어서 달리고 메모리가 늘지 않는다 |

순서의 이유: 교통 차량(9)은 차량 모델(6)과 차로·신호(8)가 있어야 만들 수 있다. 보행자(10)는 보행 신호(8)가 있어야 한다. 신호등 모델(11)은 신호 체계(8)의 겉모습이라 뒤에 와도 된다. 건물과 도로 구조는 다른 단계에 의존하지 않아 순서를 바꿀 수 있다.

## 4. 6~7단계: 차량

### 4.1 6단계: 외관

지금 차체는 옆모습 윤곽 하나를 폭 방향으로 밀어낸 것이다. 위에서 보면 직사각형이고 앞뒤가 평평하다.

| 요소 | 내용 |
|---|---|
| 차체 | 길이 방향 단면 여러 장을 이어 곡면으로 만든다. 보닛 굴곡, 좁아지는 지붕, 둥근 모서리, 휠 아치가 생긴다 |
| 차종별 형태 | 해치백(짧은 뒤), 세단(3박스), 쿠페(낮고 긴 보닛), SUV(높은 차체와 지상고). 가상 차량이고 실제 차를 본뜨지 않는다 |
| 등화류 | 전조등·주간주행등·후미등·제동등·후진등·방향지시등이 각각 켜진다 |
| 디테일 | 그릴, 범퍼, 사이드미러, 도어 손잡이와 분할선, 와이퍼, 안테나, 배기구, 한국식 번호판(지어낸 번호) |
| 휠 | 차종별 휠 디자인, 타이어 옆면, 브레이크 디스크. 조향과 회전은 지금처럼 동작 |
| 도장 | 메탈릭·솔리드 선택, 색상 팔레트 확대, 유리 틴팅 |
| 조작 | 방향지시등(좌·우·비상), 경적. 방향지시등은 핸들이 돌아오면 꺼진다 |
| 날씨 반응 | 비에 젖은 차체 광택, 눈 올 때 지붕에 쌓인 눈 |

제작 방식은 11장 결정 1에 따른다. 권장은 코드로 만드는 곡면 차체다. 내려받는 용량이 거의 없고 이용 조건 문제가 없다.

### 4.2 7단계: 실내

| 요소 | 내용 |
|---|---|
| 계기판 | 속도계·회전계 바늘, 기어, 연료·수온(고정값), 방향지시등·전조등·상향등 표시등. 밤에는 조명 |
| 센터 화면 | 라디오 채널과 곡명, 진행 방향 지도. 화면 위 겹쳐 그리던 정보를 실내로 옮긴다 |
| 핸들 | 지금의 회전에 더해 스포크, 경적 패드, 레버(방향지시등·와이퍼)가 움직인다 |
| 거울 | 룸미러와 좌우 사이드미러에 뒤쪽이 비친다. 품질 낮음에서는 끈다 |
| 실내 구조 | 대시보드, A필러, 도어 트림, 시트, 헤드레스트, 센터 콘솔, 변속 레버. 차종별로 다르다 |
| 시선 | 마우스나 오른쪽 스틱으로 좌우를 둘러본다. 회전할 때 시선이 진행 방향으로 조금 돌아간다 |
| 시점 추가 | 보닛 시점, 자유 회전 시점(차 주위를 돌려 본다) |

거울은 장면을 한 번 더 그리므로 비용이 크다. 작은 해상도로 그리고, 세 거울을 한 번에 그리는 방법(뒤쪽 한 장을 나눠 쓰기)을 먼저 시도한다.

## 5. 8~9단계: 교통

### 5.1 8단계: 차로와 신호 체계

눈에 보이는 것은 적지만 교통과 보행자의 바탕이다.

| 요소 | 내용 |
|---|---|
| 차로 도로망 | 지금 도로망은 도로 중심선 단위다. 이를 차로 단위로 나눈다: 차로별 중심선, 방향, 좌회전·직진·우회전 허용 |
| 교차로 경로 | 교차로마다 들어오는 차로에서 나가는 차로로 이어지는 곡선 경로를 만든다 |
| 차로 정보 보완 | 지도에 차로 수가 있는 구간은 일부뿐이다. 등급별 기본값을 쓰고, 일방통행·회전 제한은 지도 값을 따른다 |
| 신호 현시 | 한국식 4색(적·황·좌회전 화살표·녹): 직진과 좌회전 분리, 방향별 순서. 작은 교차로는 2현시 |
| 보행 신호 | 횡단보도마다 보행 신호와 남은 시간. 차량 신호와 맞물린다 |
| 비신호 교차로 | 우선도로 규칙과 일시정지 |
| 노면 표시 | 차로별 진행 방향 화살표, 좌회전 유도선, 유턴 표시가 이 자료에서 나온다 |

검증: 모든 교차로에 대해 "서로 부딪히는 경로가 동시에 녹색이 되지 않는다", "모든 차로에서 나갈 길이 있다"를 프로그램으로 검사한다.

### 5.2 9단계: 교통 차량

| 요소 | 내용 |
|---|---|
| 주차 차량 | 이면도로 가장자리와 주차장에 서 있는 차. 움직이지 않아 싸고, 거리가 가장 빨리 살아난다. 먼저 넣는다 |
| 주행 차량 | 차로를 따라 달린다. 앞차와 간격 유지, 제한속도, 신호 준수, 교차로에서 방향 선택, 방향지시등·제동등 점등 |
| 플레이어 반응 | 플레이어 차를 장애물로 본다. 앞에 있으면 멈추고, 오래 막히면 경적 |
| 차로 변경 | 처음에는 넣지 않는다. 교차로에서만 차로를 고른다. 기본 동작이 안정된 뒤 추가한다 |
| 차종 | 플레이어 4종의 단순화 판에 더해 택시, 시내버스, 소형 트럭, 승합차. 버스는 정류장에 선다 |
| 생성과 제거 | 플레이어 주변 약 300m 안, 시야 밖에서 나타나고 멀어지면 사라진다 |
| 수량 | 낮음 8대, 보통 20대, 높음 40대(주행 차량 기준, 측정 후 조정). 메뉴에서 교통량 없음·적음·보통 선택 |
| 시간대 | 밤과 새벽은 적고 낮과 노을은 많다. 밤에는 전조등을 켠다 |
| 충돌 | 플레이어와 부딪히면 양쪽 다 밀려 멈춘다. 파손은 없다 |
| 물리 | 교통 차량은 경로 위를 움직이는 단순 운동이다. 플레이어 차의 물리를 쓰지 않는다 |

위험은 교착이다. 교차로 안에 차가 서서 서로 막는 상황을 막기 위해 "나갈 자리가 있을 때만 교차로에 진입" 규칙을 두고, 그래도 일정 시간 못 움직인 차는 시야 밖에서 제거한다.

## 6. 10단계: 보행자

| 요소 | 내용 |
|---|---|
| 보행망 | 인도, 횡단보도, 보행로(해변 산책로, 공원길)를 잇는 그물망 |
| 모습 | 단순한 인체 모델 여러 종(성별·연령·옷 색 조합). 걷는 동작이 있다. 얼굴 디테일은 없다 |
| 행동 | 인도를 걷고, 보행 신호를 기다렸다 건넌다. 버스 정류장과 신호 대기 지점에 서 있는 사람 |
| 날씨·시간 | 비에는 우산을 쓰고 수가 준다. 밤과 새벽은 적다. 해변과 상가 거리는 많다 |
| 수량 | 낮음 0명, 보통 30명, 높음 80명(측정 후 조정). 한 번에 그리는 방식으로 묶어 그린다 |
| 차와의 관계 | 11장 결정 2에 따른다. 권장: 차가 다가오면 사람이 물러서고, 닿기 전에 플레이어 차가 강제로 감속한다. 다치는 묘사는 없다 |
| 교통 차량 | 횡단 중인 사람이 있으면 기다린다 |

## 7. 11~12단계: 거리와 건물

### 7.1 11단계: 신호등·표지·가로 시설

| 요소 | 내용 |
|---|---|
| 신호등 | 기둥과 가로 팔이 있는 한국식 가로형. 4색등, 보행 신호등, 남은 시간 표시기. 8단계의 현시대로 켜진다 |
| 방향 표지 | 간선 교차로 앞의 녹색 방향 표지. 도로망에서 각 방향의 도로명과 지명(해운대해수욕장, 달맞이길, 광안대교 등)을 뽑아 만든다 |
| 규제·안내 표지 | 제한속도, 일방통행, 진입금지, 유턴, 횡단보도, 어린이보호구역, 주정차 금지 |
| 도로명판 | 지금 것을 실제 규격 비율로 다듬는다 |
| 5장에서 빠진 것 | 과속방지턱, 어린이보호구역 노면(적색 포장), 전봇대와 전선, 버스 정류장, 가드레일, 중앙분리대 |
| 그 밖 | 볼라드, 무단횡단 방지 울타리, 과속 단속 카메라 함, 맨홀, 소화전, 자판기, 현수막 |
| 나무 | 은행나무·벚나무·소나무 구분. 해변로는 소나무 |

### 7.2 12단계: 건물

| 요소 | 내용 |
|---|---|
| 외벽 다양화 | 유형당 무늬를 여러 장으로 늘리고, 건물마다 색·창 간격·층고를 달리한다 |
| 1층 | 상가 건물 1층에 진열창, 출입문, 차양. 아파트는 필로티와 현관 |

## 13. 6단계 결과: 차량 외관 (2026-11-22)

| 요소 | 넣은 것 |
|---|---|
| 차체 | 길이 방향 단면 60~70장을 이어 만든 곡면 차체(`src/carbody.js`). 보닛 굴곡, 안으로 기운 옆 유리, 둥근 앞뒤 끝, 휠 아치가 있다. 차 한 대는 삼각형 약 2만 6천 개 |

| 디테일 | 그릴과 흡기구, 한국식 번호판(지어낸 번호), 사이드미러, 도어 분할선과 손잡이, 와이퍼, 샤크핀 안테나, 배기구 |
| 휠 | 차종별 스포크(5·10·쌍5·6), 타이어 옆면 곡선, 브레이크 디스크와 캘리퍼(쿠페는 적색) |
| 도장 | 색상 10종. 색마다 메탈릭 정도가 다르다. 비가 오면 차체가 더 번들거리고, 눈이 오면 보닛과 지붕이 하얘진다 |
| 조작 | `Q`/`E` 방향지시등(핸들을 돌렸다가 풀면 꺼짐), `F` 비상등, `H` 경적. 게임패드는 LB/RB, Y, 왼쪽 스틱 누르기. 화면에 깜빡이 화살표, 깜빡이 소리 |

확인

- 4종을 앞·옆·뒤·위 여섯 방향에서 찍어 형태를 봤다(`src/dev/carsheet.js`). 밤의 전조등·제동등·비상등, 눈 쌓인 모습, 운전석 시점도 화면으로 확인했다.
- 자동 운전: 마린시티 순환 2.28km를 4종 모두 충돌 없이 완주. 차체 모양만 바뀌고 충돌 크기와 물리는 그대로다.
- 방향지시등: 직진 중에는 유지, 그 방향으로 돌고 나면 꺼짐, 반대 방향으로 돌 때는 유지, 비상등은 비상등 키로만 꺼짐.
- 경적과 깜빡이 소리가 실제로 출력되는 것을 신호 크기로 확인. 창이 포커스를 잃으면 경적이 멎는다.
- 프레임(Intel Iris Xe, 1280×720, 보통 품질, 메뉴 화면): 맑은 낮 59, 비 오는 밤 57. 성능 예산 안이다.
- 별도 검토자의 코드 검토에서 차단할 결함은 없었고, 지적된 4건(창 전환 시 경적이 계속 울림, 방향지시등 키가 비상등을 끔, 후진 중 제동등, 경적이 음량 설정을 무시)을 고쳤다.

**기획 대비 빠진 것**

- 도장의 메탈릭·솔리드를 따로 고르는 기능과 유리 틴팅 선택은 없다. 색마다 정해져 있다.
- 와이퍼 모델은 움직이지 않는다(비 올 때 운전석 화면의 와이퍼는 3단계 것 그대로).

**알려진 한계**

- "차종이 구분되고 차답게 보이는가"는 사람이 보고 판단해야 한다. 형태는 단면 몇 장의 수치로 정한 것이라 실제 차만큼 면이 정교하지 않고, 옆면에 캐릭터 라인이 없다.
- 전조등·후미등·그릴은 차체 앞뒤 면에 붙인 조각이라 네모난 모양만 된다.
- 차 그림자에 줄무늬가 생긴다. 그림자 지도가 320m 범위에 2048칸이라 한 칸이 16cm이기 때문이고, 이전 차체에서도 같았다.
- 실내는 좌석·대시보드 자리만 잡은 상자다. 7단계에서 만든다.
- 도어 분할선은 1픽셀 선이라 가까이에서는 가늘다.

- 운전석에서 화면 정보가 숨고 `U`로 돌아오는 것, 마우스로 46도 돌렸다 놓으면 0도로 돌아오는 것, `C` 세 번에 추적 시점으로 돌아오는 것을 확인했다.
- 자동 운전: 마린시티 순환 2.28km를 4종 모두 충돌 없이 완주.
- 운전석 시점 프레임(Intel Iris Xe, 1280×720): 낮음 60, 보통 맑은 낮 55~60·비 오는 밤 39~43, 높음 맑은 낮 52·비 오는 밤 26~33. 보통 품질의 비 오는 밤이 예산(40) 경계에 있어 거울 갱신 간격을 한 단계 더 늘렸다(4프레임마다).
- 별도 검토자의 코드 검토에서 차단할 결함은 없었다. 거울의 좌우 대응은 맞다고 확인받았고, 지적된 8건(룸미러가 조수석 쪽을 향함, 거울 속 젖은 노면 반사가 어긋남, 거울을 그릴 때 전조등 조명이 빠져 셰이더를 다시 고름, 마우스 끌기가 풀리지 않는 경우 등)을 고쳤다.

**기획 대비 빠진 것**

- 연료·수온 게이지는 넣지 않았다(값이 변하지 않아 뺐다).
- 회전할 때 시선이 진행 방향으로 도는 것은 1단계의 것 그대로다. 새로 손보지 않았다.

**알려진 한계**

- 실내에는 조명 계산이 없다. 낮에는 재질이 스스로 조금 빛나게 해서 밝기를 맞췄고, 그림자와 햇빛 무늬는 없다.
- 거울은 진짜 반사가 아니라 차 뒤에서 뒤쪽을 찍은 한 장을 나눠 보여 준다. 고개를 돌려도 비친 모습이 바뀌지 않고, 내 차의 옆면이나 뒷좌석은 비치지 않는다. 보통 품질에서는 초당 약 15번만 갱신된다.
- 높음 품질의 비 오는 밤 운전석 시점은 26~33프레임이다. 노면 반사와 거울을 둘 다 그리기 때문이다.
- 계기판 글자는 1280×720 화면에서 작다. 그래서 `U` 키를 두었다.
- 사이드미러 유리가 보는 각도에 따라 하우징과 조금 어긋나 보인다.
- 운전자 모습(손, 몸)은 없다.

## 15. 8단계 결과: 차로와 신호 체계 (2026-11-22)

교통 차량과 보행자가 쓸 자료를 만드는 단계다. 화면에 보이는 것은 노면 화살표, 정지선, 4색 신호등이다. 자료는 게임을 열 때 지도에서 계산한다(약 0.1초, `src/map/lanes.js`).

| 요소 | 넣은 것 |
|---|---|
| 차로 도로망 | 차로 1,582개(139km). 차로마다 방향, 중심선, 어느 교차로에서 와서 어느 교차로로 가는지를 가진다 |
| 교차로 | 364곳. 가까이 붙은 교차점(분리된 도로가 만나는 곳)은 하나의 교차로로 묶었다. 가지가 6개를 넘는 엉킨 곳(회전교차로 등 15개 지점)은 묶지 않고 짧은 차로로 남겼다 |

| 노면 표시 | 차로별 진행 방향 화살표(직진, 좌, 우, 겸용), 기다려야 하는 진입로에만 정지선 |
| 신호등 | 좌회전 화살표가 있는 4색등(적·황·화살표·녹)과 3색등. 교차로마다 제 신호 순서대로 켜진다 |

확인

- 검사 도구(`npm run lanes:check`)가 통과한다. 검사 내용: 모든 차로가 양 끝에서 교차로에 붙어 있다, 진행 경로 길이가 90m 미만이다, 신호 교차로에서 서로 가로막는 두 경로가 동시에 녹색이 되지 않는다(양보 표시가 붙은 비보호 좌회전 제외), 모든 경로가 한 주기에 한 번은 녹색을 받는다, 모든 신호등이 항상 적·황·녹 중 정확히 하나를 켠다, 보행 신호가 걸음일 때 그 가지에서 차가 나오거나 직진 차가 들어오지 않는다.
- 차로의 89.7%가 서로 오갈 수 있는 한 덩어리다. 갈 곳이 없는 차로 17개는 모두 지도 가장자리다.
- 교차로 평면도(`src/dev/lanesheet.js`)로 4지, T자, 5~6지, 회전교차로, 비신호 교차로의 경로와 신호 상태를 그림으로 확인했다.
- 게임 화면에서 노면 화살표, 정지선, 4색 신호등을 확인했다. 자동 운전은 순환 2.28km와 달맞이길 4.78km를 4종 모두 충돌 없이 완주했다.
- 별도 검토자의 코드 검토에서 차단할 결함은 없었다. 좌우 방향 규칙은 일관된다고 확인받았고, 지적된 6건(홀수 차로 도로의 중앙선 위치, 이면도로 횡단보도가 1m로 짧아짐, 도로가 갈라지는 곳에 불필요한 신호, 155도 넘는 급회전 경로 52개 누락 등)을 고쳤다.

**기획 대비 빠진 것**

- 좌회전 유도선과 유턴 표시는 넣지 않았다. 유턴은 막다른 길에서만 허용한다.
- 보행 신호등과 남은 시간 표시기는 자료만 있고 화면에는 없다. 11단계에서 만든다.

**알려진 한계**

- 지도 자료에 신호등 위치, 차로별 진행 방향, 회전 제한이 없다. 그래서 신호 교차로는 "간선급 도로 가지가 3개 이상 만나는 곳"으로, 차로 배정은 규칙으로 정했다. 실제와 다를 수 있다.
- 신호 시간은 교차로마다 같은 규칙이고 서로 맞물리지 않는다(연동 없음).
- 신호 교차로의 가지 16개는 보행 신호가 걸음이 되는 때가 없다. 불규칙한 교차로에서 생긴다.
- 반지름 3m 미만으로 꺾이는 경로가 250개 있다. 좁은 이면도로 교차점이라 차가 천천히 돌아야 한다.
- 교량·고가 41구간과 진입로(서비스 도로)는 도로망에서 빠져 있다. 13단계에서 교량을 넣으면 연결이 늘어난다.
- 이 단계의 자료는 아직 아무도 쓰지 않는다. 실제로 차가 다녀 봐야 드러나는 문제는 9단계에서 나온다.

## 16. 9단계 결과: 교통 차량 (2026-11-22)

| 요소 | 넣은 것 |
|---|---|
| 주행 차량 | 차로를 따라 달린다. 앞차와 간격 유지, 제한속도, 굽은 길과 회전 전 감속, 신호 준수(황색에서는 설 수 있으면 선다), 비신호 교차로의 양보와 일시정지, 방향지시등과 제동등 |
| 교차로 통과 | 가로막는 경로에 차가 없고 건너편 차로에 자리가 있을 때만 진입한다. 회전교차로처럼 짧은 차로가 이어진 곳은 끝까지 비어 있을 때 한 번에 지나간다 |
| 플레이어 반응 | 진행 경로 위에 플레이어 차가 있으면 약 2.5m 뒤에 선다. 5초 넘게 막히면 경적을 울린다. 부딪히면 플레이어 차는 밀려나고 상대 차는 잠시 멈춘다. 파손은 없다 |
| 차종 | 세단, 해치백, SUV, 스포츠 쿠페(플레이어 차의 저해상도판)와 택시, 승합차, 1톤 트럭, 시내버스. 버스는 간선도로에만 나온다 |
| 생성과 제거 | 플레이어에서 90~330m 떨어진, 카메라에 보이지 않는 차로에서 나타나고 400m 밖에서 사라진다. 50초 넘게 꼼짝 못 한 차는 보이지 않을 때 치운다 |
| 수량 | 품질 낮음 8대, 보통 20대, 높음 40대. 메뉴의 "교통량"에서 없음·적음·보통을 고른다. 밤은 45%, 새벽은 50%로 줄어든다 |
| 주차 차량 | 진입로와 주차장 통로(서비스 도로) 옆에 구역당 최대 14대. 충돌 판정이 있다 |

확인

- 모의 주행 검사(`npm run traffic:check`): 게임 없이 교통만 30분씩 네 곳(마린시티, 해운대 시내, 달맞이길 입구, 센텀 쪽)에서 차 40대로 돌린다. 차끼리 겹침 0건, 적색 신호 진입 0건. 2시간 합계로 교차로 통과 8,900여 회, 꼼짝 못 해 치운 차 7대(모두 해운대 시내와 마린시티의 교차로). 평균 속도 17~22km/h, 움직이는 차의 비율 61~100%.
- 게임 화면에서 낮과 밤에 차가 다니는 모습, 룸미러에 비친 뒤차, 택시·트럭·승합차·주차 차량을 확인했다.
- 플레이어와의 상호작용: 달리던 차 앞 35m에 서 있으면 2.45m 뒤에 멈추고 8초 안에 경적을 한 번 울린다. 그 차를 향해 후진하면 0.25m에서 막히고 지나가지 못한다.
- 프레임(Intel Iris Xe, 1280×720, 추적 시점): 낮음 60, 보통 맑은 낮 54~57·비 오는 밤 41~46, 높음 맑은 낮 41·비 오는 밤 27. 교통을 끈 것과 차이가 1프레임 안쪽이다. 준비 시간은 약 1초로 그대로다.
- 자동 운전(교통 끔): 순환 2.28km와 달맞이길 4.78km를 4종 모두 충돌 없이 완주.
- 별도 검토자의 코드 검토에서 수정 요청 2건(교통량을 "없음"으로 바꾸면 차 모습이 남음, 교차로 진입 허가를 너무 쉽게 반납해 순서를 뺏김)과 그 밖의 5건을 받아 모두 고쳤다. 플레이어 감지를 직선이 아니라 실제 진행 경로로 바꾼 것이 그중 하나다.

만들면서 바꾼 것

- 처음에는 차를 인스턴싱으로 그렸는데, 매 프레임 인스턴스 버퍼를 다시 쓰는 것만으로 내장 그래픽에서 프레임이 7ms씩 늘었다. 차마다 메시 하나(색과 등화는 셰이더 값)로 바꿔 해결했다.
- 주차 차량이 처음에 400대, 삼각형 280만 개가 되어 보통 품질이 41프레임까지 떨어졌다. 주차용 저해상도 차체(대당 약 1,500개)와 구역당 14대 상한으로 줄였다.
- 8단계 자료를 실제로 써 보니 드러난 문제를 고쳤다: 좁은 각도로 갈라지는 길의 차로가 겹침, 길이 꺾이며 이어지는 곳의 차로가 겹침, 스치듯 지나는 경로가 충돌 목록에서 빠짐.

**기획 대비 빠진 것**

- 차로 변경은 없다(기획대로). 그래서 앞에 느린 차가 있어도 추월하지 않는다.
- 버스가 정류장에 서지 않는다. 정류장이 아직 없다(11단계).
- 교통 차량의 엔진 소리는 없다(14단계).

**알려진 한계**

- 교통 차량은 플레이어 차보다 단순한 모델이다(대당 삼각형 약 3천 개, 실내 없음, 바퀴가 돌지 않음). 밤에 전조등이 길을 비추지 않고 빛나기만 한다.
- 30분에 한두 대꼴로 교차로에서 오래 막힌 차를 치운다. 보이지 않을 때 치우지만 2분을 넘기면 보이는 곳에서도 사라진다.
- 차가 지도 가장자리와 일방통행 막다른 길에서 사라진다. 플레이어가 그 근처에 있으면 보인다.
- 신호 교차로 진입로 191곳 중 신호등이 서 있는 곳은 약 110곳이다. 기둥 자리가 차도나 건물과 겹치면 세우지 않기 때문이다. 신호등이 안 보여도 교통은 신호대로 움직인다. 11단계에서 신호등 위치를 다시 잡는다.
- 플레이어가 신호를 어기거나 역주행해도 교통 차량은 피하지 않고 멈추기만 한다.
- 교통 차량은 물리 없이 경로 위를 움직인다. 빗길·눈길에서도 미끄러지지 않는다.
- "교통이 자연스러워 보이는가"는 사람이 직접 달려 보고 판단해야 한다.

확인

- 모의 검사(`npm run people:check`): 사람 80명과 차 40대를 20분씩 세 곳(마린시티, 해운대 시내, 공원 산책로)에서 함께 돌린다. 차와 사람이 같은 자리에 놓인 경우 0건. 횡단 640회, 90초 넘게 기다린 사람 0명, 걷고 있는 비율 92~99%.
- 차로 사람에게 달려드는 시험(공원 보행로, 가속 페달을 끝까지 밟고 9초, 5회): 한 번도 닿지 않았다. 가장 가까웠던 거리는 0.54m이고 자동 제동이 걸렸다. 다만 가장 가까이 지날 때 속도가 시속 42~50km였던 경우가 3회 있다. 사람이 비켜서 닿지는 않았지만, 차를 그 전에 다 세우지는 못한다는 뜻이다.
- 게임 화면에서 인도를 걷는 사람, 횡단보도를 건너는 사람, 비 올 때 우산을 확인했다.
- 프레임(Intel Iris Xe, 1280×720, 추적 시점): 보통 맑은 낮 55~59·비 오는 밤 41~55, 높음 맑은 낮 45·비 오는 밤 31. 사람을 숨긴 것과 차이가 측정 오차 안이다.
- 교통 검사와 자동 운전(순환 2.28km, 달맞이길 4.78km, 4종 무충돌)을 다시 통과했다.
- 별도 검토자의 코드 검토에서 수정 요청을 받았다. 건널 수 없는 횡단보도 앞에서 영원히 기다리는 사람, 차도에 끊긴 보행로가 인도와 이어지지 않음, 차도를 가로지르는 모서리 연결 17개, 두 갈래 이음부의 중복 연결을 고쳤다. 횡단보도 위 사람 수 집계는 검토자가 따로 돌려 본 결과 어긋남이 없었다.

**기획 대비 빠진 것**

- 버스 정류장에 서 있는 사람은 없다. 정류장이 아직 없다(11단계).
- 사람에게 그림자가 없다. 그림자를 켜면 접은 우산까지 그림자가 생겨 뺐다.
- 해변과 상가 거리에 사람이 더 많이 나오게 하는 처리는 "보행로와 간선도로에 가중치"까지만 했다. 해변 백사장에는 사람이 없다.

**알려진 한계**

- 횡단보도 1,098곳 중 331곳은 사람이 쓰지 않는다. 길이 좁은 각도로 만나 횡단보도 끝이 다른 차도 위에 놓이는 곳이다. 그림은 그려져 있다.
- 신호 교차로의 가지 15개는 보행 신호가 걸음이 되지 않아 사람이 건너지 않는다(8단계의 한계).
- 사람은 서로를 피하지 않아 겹쳐 지나갈 수 있다. 건물 출입, 앉기, 서서 이야기하기 같은 행동은 없다.
- 차를 피할 때 건물 벽이나 차도 쪽인지 가리지 않고 옆으로 비킨다.
- 교차로 모서리에 인도 포장이 없어(2단계의 한계) 사람이 맨땅을 밟고 모서리를 돈다. 13단계에서 모서리 포장을 만든다.
- "사람이 자연스러워 보이는가"는 직접 보고 판단해야 한다.
